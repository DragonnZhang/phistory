## Qoder startup failure and capture repair

The initial `1.1.82` attempt reported TLS handshake timeouts for `api1.qoder.sh`, `center.qoder.sh` and `api2.qoder.sh`, plus a failed HTTPDNS connection to `203.107.1.1:443`, before producing any valid prompt request. The [targeted backfill retry](https://github.com/DragonnZhang/phistory/actions/runs/41777281458) used only `qoder/default`, exact range `1.1.82` to `1.1.82`, `force=false`, and `smoke=true`. It also completed with failure: the CLI exited with code 1, `api_calls: 0`, and `no valid records found in trace file`. It committed no new capture; its independent smoke was correctly skipped after the archive failed.

Further Linux diagnostics identify the blocking error before request construction:

- [Same-runner comparison](https://github.com/DragonnZhang/phistory/actions/runs/41783426200): `1.1.81` captures successfully with the same credential, while `1.1.82` records `ModelNotFoundError: main model "auto" is unavailable.` in its native log.
- [Model-selection observation](https://github.com/DragonnZhang/phistory/actions/runs/41784125580): authentication succeeds, the model catalog returns HTTP 200 and 15 entries, and `auto` exists with the expected `qoder` source but `enabled: false`. Passing only the PAT instead of both supported credential aliases produces the same result. The temporary observation prints these fields without changing selection logic; it is diagnostic evidence, not a published capture.
- [Unmodified CLI check](https://github.com/DragonnZhang/phistory/actions/runs/41785197056): native `--list-models` exits successfully and lists only `Qwen3.8-Flash` for this credential. The default capture still fails with the same native model error. Official JSON output hides that cause behind a generic `error_code: 500`, so changing output format would not repair the diagnostic gap.

The exact `1.1.82` bundle rejects a selected model whose catalog entry has `enabled: false`. The [official model guide](https://docs.qoder.com/cli/model) still describes Auto as the default; it also documents the account-specific `--list-models` check. This establishes the current credential's catalog restriction, not why the service disabled Auto. Expired authentication, exhausted credits, global Auto retirement, and a broken request hook are not established. The older release reaching the capture boundary does not verify live model access.

Phistory now extracts only the recognized native model-selection error from newly written log bytes while the isolated HOME still exists. It reports that reason directly as the failed capture, so GitHub's 500-character annotation and summary limits cannot hide it behind setup logs. The failure stops the session-persistence fallback and generic empty-trace retries. Full native logs and account data are not copied into artifacts. Transient failures retain their bounded retries; an already captured prompt remains valid even if the CLI later reports an error. Four fake-CLI regressions cover fail-fast behavior, credential redaction, preservation of existing archives, stale-log exclusion, transient retry, valid-prompt retention, and the full reason appearing in GitHub annotations and summaries. All 183 tests, Ruff, and the package build pass.

The [main-branch verification](https://github.com/DragonnZhang/phistory/actions/runs/41786317837) runs the exact `1.1.82` target with the unmodified official CLI and the original default arguments. All 183 Linux tests pass; the capture stops after one attempt and exposes `Qoder CLI model selection failed: main model "auto" is unavailable.` It produces no new archive, and its fresh-cache smoke is correctly skipped. This verifies failure reporting and bounded execution, not restoration of model availability; the workflow remains failed. A subsequent formatting regression ensures that the same native reason is also visible in the GitHub annotation and summary.

### Capture-only startup mock

The model request has always been intercepted by claude-tap and answered with a dummy response. The failed live step was startup authentication/catalog validation, before request construction. The capture driver now supplies a narrowly scoped startup mock: a Node preload enables only an existing official `auto` entry in a decoded `assistant` catalog. It leaves all other server model fields, every other entry, the default CLI arguments, and the installed npm package unchanged. It never invents a model absent from the catalog. The request's system prompt and tools continue to be assembled by the official CLI.

The preload requires both `PHISTORY_QODER_CAPTURE_BOOTSTRAP=model-availability` and claude-tap's capture-only marker. It records the mock before applying it; successful capture metadata includes the mode in `capture_environment` and the applied condition in `compatibility_patches`. Model generation still terminates at the local capture proxy. This models an available Auto entry for prompt extraction and does not establish account access to the real model. BYOK configuration and a real provider API key are unnecessary for this capture path.
